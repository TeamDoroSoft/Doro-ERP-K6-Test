# Doro ERP 시연 시나리오

목표 분량 3~5분 · 작성일 2026-08-27 · v2 (키오스크 도메인 분리 반영)

---

## 0. 이 영상의 한 문장

> "매장 하나를 처음부터 열어서, 손님 주문 한 건이 주방까지 도착하는 것을 끊김 없이 보여준다."

기능을 하나씩 나열하지 않는다. **하나의 이야기**로 이어 붙인다. 심사자가 "그래서 이게 뭘 하는 시스템인데?"를 영상 끝에 묻지 않게 하는 것이 유일한 성공 기준이다.

---

## 1. 준비물

촬영 전에 아래가 모두 준비되어 있어야 한다. 하나라도 없으면 촬영 중 끊긴다.

| # | 항목 | 비고 | 완료 |
| ---: | --- | --- | :---: |
| 1 | 시연 전용 업체 + OWNER 계정 | Provider Admin에서 수동 생성 | ☐ |
| 2 | 브라우저 창 2개 | POS용 / 키오스크용. 키오스크는 시크릿 창 권장 | ☐ |
| 3 | 카테고리·상품 3~4개 | 이름이 알아보기 쉬운 것 (아메리카노, 라떼…) | ☐ |
| 4 | 테이블 2~3개 | 매장 주문을 보여줄 경우에만 | ☐ |
| 5 | 화면 녹화 도구 | 두 창을 동시에 담을 수 있는 해상도 | ☐ |
| 6 | 결제 방식 결정 | 2장 참조 | ☐ |

**창 배치** — 좌측 POS, 우측 키오스크로 고정한다. 영상 내내 위치를 바꾸지 않는다. 시청자가 "왼쪽은 직원, 오른쪽은 손님"을 한 번만 학습하면 되도록 한다.

**주소가 다르다** — 2026-08-26 변경으로 키오스크가 별도 출처로 분리되었다.

| 화면 | 주소 |
| --- | --- |
| POS (직원) | `doro.minseok.click` |
| 키오스크 (손님) | `kiosk.minseok.click` |
| Provider Admin | `admin.doro.minseok.click` (내부 전용, SSM 터널 필요) |

키오스크 주소의 루트(`/`)로 들어가면 활성화 화면으로 자동 이동한다. POS 주소에서 `/kiosk`로 들어가면 키오스크 주소로 넘어가므로, 촬영 중 주소를 잘못 치면 화면이 튄다. **주소창을 미리 각 창에 열어두고 시작한다.**

---

## 2. 결제를 어떻게 보여줄 것인가 — 결정 필요

두 가지 방식이 있다. 촬영 전에 하나를 골라야 한다.

### A안 — 토스 테스트 결제까지 실제로

키오스크에서 결제 버튼을 누르고, 토스 테스트 결제창에서 테스트 카드로 승인까지 진행한다.

- **장점** — 실제 서비스와 동일. "결제까지 붙였다"가 눈으로 증명된다
- **단점** — 결제창이 뜨는 데 시간이 걸리고, 실패하면 촬영을 다시 해야 한다
- **준비** — 토스 테스트 키가 환경에 설정되어 있어야 함

### B안 — 결제창까지만 보여주고 넘어감

결제창이 뜨는 것까지 보여주고, "결제 승인 과정은 생략합니다" 자막과 함께 이미 결제된 주문 화면으로 전환한다.

- **장점** — 촬영이 안정적. 재촬영 위험이 없다
- **단점** — 흐름이 한 번 끊긴다
- **준비** — 미리 결제 완료된 주문을 하나 만들어 둘 것

> **권장** — 첫 촬영은 A안으로 시도하고, 두 번 실패하면 B안으로 전환한다. 결제 승인이 눈앞에서 되는 장면은 설득력이 크므로 한두 번은 시도할 가치가 있다.

## 3. 시연 흐름 (3~5분)

### 장면 1 — 매장 준비 (60초)

**보여줄 것**: 좌측 POS 창

| 순서 | 화면 | 행동 |
| ---: | --- | --- |
| 1 | 로그인 | 점주 계정으로 로그인 |
| 2 | 메뉴 관리 | 상품 1개 추가 (예: 아메리카노 4,000원) |
| 3 | 매장·직원 설정 → 키오스크 기기 | 기기 코드 `kiosk-01` 입력 → **기기 등록** |
| 4 | 기기 활성화 정보 | **기기 코드 복사 / 비밀값 복사** 버튼으로 각각 복사 |
| 5 | (선택) 기기 목록 | 방금 등록한 기기가 목록에 나타난 것 확인 |

**말할 것 (자막 또는 내레이션)**

> "점주가 매장을 엽니다. 메뉴를 등록하고, 매장에 놓을 키오스크를 시스템에 등록합니다.
> 등록하면 그 기기 전용 비밀값이 발급됩니다. 이 값은 이 순간 한 번만 보여집니다."

**촬영 포인트** — 비밀값이 뜨는 순간 잠깐 멈춘다(1~2초). 화면에 *"이 창을 닫으면 다시 확인할 수 없습니다"* 문구가 함께 뜨므로, 그 문구까지 화면에 잡히게 한다. 여기가 보안 설계를 어필하는 지점이다.

**주의** — 이 창을 닫으면 비밀값은 정말로 다시 못 본다. 닫기 전에 복사해 두고, 실수로 닫았다면 **새로 발급**(rotate)을 눌러 다시 받는다. 재촬영할 필요는 없다.

---

### 장면 2 — 키오스크 연결 (30초)

**보여줄 것**: 우측 키오스크 창

| 순서 | 화면 | 행동 |
| ---: | --- | --- |
| 1 | `kiosk.minseok.click` | 활성화 화면으로 자동 이동. "활성화 정보가 없습니다" 상태를 먼저 보여줌 |
| 2 | 키오스크 연결 폼 | 업체 코드 / 기기 코드 / 비밀값 입력 |
| 3 | 메뉴 화면 | 연결 성공 → 방금 등록한 메뉴가 그대로 등장 |

**말할 것**

> "설치된 키오스크에 방금 받은 값을 입력합니다.
> 연결되는 순간, POS에서 등록한 메뉴가 그대로 넘어옵니다. 따로 옮기는 작업은 없습니다."

**촬영 포인트** — 장면 1에서 등록한 상품이 여기 화면에 뜨는 것이 **이 영상의 첫 번째 하이라이트**다. 좌우 두 창이 하나의 데이터를 공유한다는 것이 시각적으로 증명되는 순간이다. 커서로 그 상품을 한 번 가리켜 준다.

---

### 장면 3 — 손님 주문 (60~90초)

**보여줄 것**: 우측 키오스크 창

| 순서 | 화면 | 행동 |
| ---: | --- | --- |
| 1 | 메뉴 | 상품 선택 → 수량 지정 → 담기 |
| 2 | 주문 확인 | 장바구니 내역·합계 확인 |
| 3 | 이용 방식 선택 | **포장** 선택 (매장 주문은 4장 참조) |
| 4 | 결제 | 2장에서 정한 A안 또는 B안 |
| 5 | 주문 상태 | **주문번호** 표시 |

**말할 것**

> "손님이 메뉴를 고르고 결제합니다. 결제가 끝나면 주문번호를 받습니다."

**촬영 포인트** — 주문번호를 화면에 크게 잡는다. 장면 4에서 같은 번호가 주방 화면에 뜨는 것으로 연결되므로, 시청자가 번호를 기억할 수 있게 2초 정도 머문다.

---

### 장면 4 — 주방 도착 (45초)

**보여줄 것**: 좌측 POS 창

| 순서 | 화면 | 행동 |
| ---: | --- | --- |
| 1 | 조리 목록 | 방금 그 **주문번호**가 목록에 떠 있음 |
| 2 | — | 조리 완료 처리 |
| 3 | 우측 키오스크 | 손님 화면의 상태가 **준비 완료**로 바뀜 |

**말할 것**

> "결제가 승인되면 주문이 주방 화면에 자동으로 뜹니다. 직원이 조리를 마치면, 손님 화면의 상태도 함께 바뀝니다."

**촬영 포인트** — 이것이 **두 번째 하이라이트**이자 영상의 결말이다. 좌측에서 버튼을 누르고 → 우측 화면이 바뀌는 것을 **한 화면 안에서** 보여준다. 컷을 나누지 않는다.

---

### 장면 5 — 마무리 (15초)

주문 목록 또는 일일 정산 화면을 잠깐 비추고 끝낸다.

> "주문 이력과 매출은 이렇게 정리됩니다."

길게 설명하지 않는다. 결말은 이미 장면 4에서 났다.

---

## 4. 매장 주문(DINE_IN)을 넣을 것인가

**넣지 않기를 권장한다.**

이유 — 현재 테이블 해제가 최대 30초 지연되는 이슈가 있다. 주문 완료 후 같은 테이블에 바로 다시 주문하면 `503` 오류 화면이 나온다. 시연 중에 이 장면이 잡히면 설명하기 어렵다.

포장 주문만으로도 전체 흐름(주문 → 결제 → 주방 → 완료)이 완전히 보여진다.

> 이슈가 해결되면 장면 3의 "이용 방식 선택"에서 **매장 식사 → 테이블 선택**을 추가한다. 테이블을 고르는 화면은 시연 효과가 좋으므로, 해결 후에는 넣을 가치가 있다.
>
> 2026-08-27 기준 미해결. `TableReservationReleaseRecovery`의 주기가 여전히 `PT30S`다.

## 5. 여유가 있을 때 추가할 장면

3~5분을 넘기지 않는 선에서, 아래 중 **하나만** 고른다.

| 장면 | 소요 | 어필 포인트 |
| --- | ---: | --- |
| **기기 폐기(revoke)** | 30초 | "키오스크를 분실하면 즉시 차단됩니다" — 보안 |
| 입장 대기 등록 | 40초 | 웨이팅 관리까지 커버 |
| 감사 로그 조회 | 30초 | 누가 무엇을 바꿨는지 추적 가능 |

**기기 폐기를 추천한다.** 장면 1~2에서 등록한 그 기기를 그대로 폐기하고, 키오스크 화면이 즉시 막히는 것을 보여주면 이야기가 닫힌다. 다른 두 개는 새로운 이야기를 열어야 해서 분량이 늘어난다.

---

## 6. 촬영 시 주의

- **로그인 비밀번호 입력 장면은 잘라낸다.** 타이핑이 그대로 녹화되면 곤란하다
- **비밀값은 이 시연용 기기의 것**이다. 영상 공개 전에 해당 기기를 폐기(revoke)하면 값이 노출되어도 무해하다
- **업체 코드에 실명이나 실제 상호를 쓰지 않는다**
- 로딩이 1초 이상 걸리는 구간은 편집에서 잘라낸다. 다만 장면 4의 주방 도착 지연은 **자르지 않는다** — 실제 동작이라는 증거다
- 한 번에 쭉 찍고 편집으로 다듬는 편이 컷을 나눠 찍는 것보다 자연스럽다
- **키오스크 창은 반드시 시크릿 창으로 연다.** POS와 도메인이 분리되었으므로 세션이 섞이지는 않지만, 이전 촬영의 활성화 상태가 남아 있으면 장면 2의 "활성화 정보가 없습니다" 화면을 못 찍는다

## 7. 촬영 전 최종 점검

| # | 확인 | 완료 |
| ---: | --- | :---: |
| 1 | 시연 업체·계정 준비됨 | ☐ |
| 2 | 상품 등록 상태 (또는 장면 1에서 등록할 것 정해둠) | ☐ |
| 3 | 결제 방식 A/B 결정 | ☐ |
| 4 | 창 2개 배치·해상도 확인 | ☐ |
| 5 | 추가 장면 1개 선택 (5장) | ☐ |
| 6 | 한 번 리허설 (녹화 없이) | ☐ |

리허설은 반드시 한다. 실제로 해보면 예상보다 오래 걸리는 구간이 반드시 나온다.
